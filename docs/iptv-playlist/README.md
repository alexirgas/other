# IPTV-плейлист: инструкция для чайников

Как устроен m3u-плейлист, как его править, как раздавать ссылкой на телевизор и не сломать кодировку.
Здесь нет ссылок на потоки, ключей и самих плейлистов, только принципы и команды.

> **Правило №1.** Плейлист содержит адреса потоков с личными ключами. Никогда не выкладывайте его в публичные репозитории, форумы и чаты.

## 1. Что такое m3u

Обычный текстовый файл. Первая строка `#EXTM3U`, дальше для каждого канала две строки:

```
#EXTINF:-1 tvg-id="id" tvg-logo="ссылка-на-логотип" group-title="ГРУППА",НАЗВАНИЕ КАНАЛА
http://адрес-потока
```

- `group-title`: папка (группа), в которой канал виден в плеере.
- `tvg-id` и `tvg-name`: по ним плеер подбирает программу передач (EPG).
- Всё после последней запятой в строке `#EXTINF` это название, которое видно на экране.
- Атрибуты пишут в двойных кавычках, без пустых строк между каналами.
- Единого официального стандарта нет, у разных плееров свои особенности.

## 2. Заголовок и программа передач (EPG)

Первая строка может нести адреса программы передач:

```
#EXTM3U url-tvg="адрес1,адрес2,адрес3" x-tvg-url="адрес1,адрес2,адрес3" refresh="86400"
```

- Несколько адресов через запятую, без пробелов.
- Не все плееры читают больше одного адреса. Если программа не подтянулась, оставьте в начале самый нужный.
- Многие плееры берут источники EPG из собственных настроек. Тогда заголовок не нужен.
- Некоторые адреса EPG содержат ваш личный номер пакета. Считайте такой адрес секретным.

## 3. Где править

Удобно вести плейлист в онлайн-редакторе (например, app.m3u.in): там видно группы, можно переносить каналы и отключать дубли. После правки скачайте готовый файл.

Порядок работы:
1. Редактируете и скачиваете файл.
2. Проверяете (раздел 6).
3. Заливаете в хранилище со ссылкой (раздел 4).
4. Обновляете плейлист в плеере.

## 4. Как раздавать ссылкой на телевизор

Плеерам на ТВ нужна ссылка. Удобный вариант: **секретный gist на GitHub**.

- Создайте gist, выберите «Create secret gist», назовите файл `playlist.m3u`.
- Ссылка вида `.../raw/playlist.m3u` (без номера ревизии) всегда отдаёт последнюю версию. Её и вставляйте в плеер.
- «Секретный» значит только «не виден в поиске». Любой, у кого есть ссылка, может читать файл. Держите ссылку в тайне.
- Если ссылка утекла, создайте новый gist и удалите старый.

## 5. Как обновлять большой файл: только через git

Если файл больше примерно 500 КБ, веб-форма gist его не принимает. В режиме редактирования файл показан обрезанным, а вставка из буфера обмена может испортить кодировку (вместо кириллицы появятся «кракозябры»).

Надёжный способ: git. Он копирует байты как есть.

Один раз склонируйте gist (подставьте свой идентификатор):

```
git clone https://gist.github.com/<ID-gist>.git iptv-gist
cd iptv-gist
git config core.autocrlf false
```

Каждое обновление:

```
Copy-Item C:\путь\к\новому\файлу.m3u .\playlist.m3u -Force
git add playlist.m3u
git commit -m "playlist: что поменялось"
git push
```

Заметки:
- `Copy-Item` это PowerShell (Windows). Подойдёт и обычное копирование файла в папку.
- Старые версии хранятся в gist во вкладке «Revisions». Это резервная копия: любую версию можно вернуть.
- При первом `git push` может открыться окно входа в GitHub. Это нормально. Пароль и токен никому не отправляйте.
- Предупреждение «LF will be replaced by CRLF» безобидно, особенно если выполнен `git config core.autocrlf false`.

## 6. Проверка перед загрузкой

- Кодировка файла **UTF-8** без BOM. В Notepad++ внизу справа должно быть написано «UTF-8».
- Первая строка начинается с `#EXTM3U`.
- За каждой строкой `#EXTINF` идёт строка со ссылкой на поток.
- Кавычки в атрибутах парные, пустых строк между каналами нет.
- Нет совпадающих по смыслу каналов-дублей (если не нужны разные версии: 4K, HD, +N часов).
- Открыли итоговую ссылку в браузере: кириллица читается нормально.

## 7. Частые проблемы

| Что видите | Причина | Что делать |
|---|---|---|
| Вместо русских букв «РџРµСЂРІС‹Р№…» | Файл прочитали или вставили не в UTF-8 | Открыть в Notepad++ или VS Code, убедиться, что UTF-8, залить через git |
| Gist пишет «file has been truncated» | Файл слишком большой для веб-редактора | Обновлять через git (раздел 5) |
| «Contents can't be empty» после «Update» | Веб-форма не отправила большой текст | То же: через git |
| В плеере старый список | Плеер или браузер кэширует ссылку | Обновить плейлист в плеере, перезапустить его, в браузере Ctrl+F5 |
| Нет программы передач | Плеер читает только первый адрес EPG или не использует заголовок | Задать EPG в настройках плеера |
| Красная кнопка «Delete» на странице gist | Удаляет **весь** gist вместе со ссылкой | Не нажимать. Удалять отдельный файл можно только значком корзины рядом с именем файла |

## 8. Безопасность коротко

- Не публикуйте плейлист, ссылку на gist, адреса EPG с личными номерами и любые токены.
- Не присылайте ключи и пароли в чаты. Помощнику (в том числе ИИ) показывайте фрагменты с замазанными ключами.
- Храните резервную копию рабочего файла на своём диске: если gist удалён, ссылка пропадёт навсегда.
