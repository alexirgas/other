# Удалённые роутеры OpenWrt + SSClash/Mihomo: безопасное обновление конфига и ядра (для чайников)

Что здесь: как с Windows 11 по ssh (через Tailscale) безопасно менять конфиг и проверять/ставить ядро Mihomo на **удалённых** роутерах, не потеряв связь.
Проверено 31.10-01.11.2026 на трёх роутерах (OpenWrt 24.10, mediatek/filogic aarch64): один локальный и два удалённых по Tailscale.

Файлы рядом:
- `cfg-rollback.sh` - самооткат: если вы за 10 минут не подтвердили, что всё хорошо, старый конфиг вернётся сам.
- `apply-config.sh` - бэкап, проверка конфига, взвод отката, подмена и перезагрузка через API.

## Главные правила (прочитайте до начала)

1. Удалённый роутер - единственный канал связи с ним это он сам. Любое действие, которое может его «положить», сначала страхуется таймером отката.
2. Конфиг меняем **перезагрузкой через API** (`PUT /configs?force=true`, ответ 204), а не рестартом службы. Рестарт перезапускает dnsmasq и nft-правила: на секунды пропадает DNS и интернет.
3. Ядро на удалённом роутере **первый раз ставим вручную**, по одному роутеру, не в окна :29-:33 и :59-:03 (в них cron обновляет списки) и не рядом с ежедневной перезагрузкой. Автоустановку (`AUTO_INSTALL=1`) включаем только после того, как ручная замена на этом роутере прошла чисто, и только с правильным `REBOOT_TIME` (см. шаг 4).
4. Всегда по одному шагу и с проверкой. Откат не снимаем, пока сами не посмотрели результат.
5. Репозиторий с конфигами - источник правды. Правим там, на роутере только забираем файл.
6. Секреты (токены, ключи, секрет API) никогда не пишем в публичный репозиторий и в команды в чате.

## Шаг 1. Доступ по ssh-ключу

На Windows (PowerShell):

```powershell
ssh-keygen -t ed25519            # если ключа ещё нет
type $env:USERPROFILE\.ssh\id_ed25519.pub
```

На роутере (OpenWrt использует Dropbear) добавьте строку ключа в `/etc/dropbear/authorized_keys` и `chmod 600` на файл.
Удобные имена в `%USERPROFILE%\.ssh\config`:

```
Host router-local
    HostName 192.168.X.1
    User root
    IdentityFile ~/.ssh/id_ed25519

Host router-remote1
    HostName 100.X.X.X      # адрес Tailscale
    User root
    IdentityFile ~/.ssh/id_ed25519
```

Проверка: `ssh router-remote1 "echo ok"` должно сразу ответить без пароля.

## Шаг 2. Подготовка на роутере (один раз)

```sh
ls /opt/clash/                      # config.yaml, bin/clash, rules/ ...
/opt/clash/bin/clash -v             # версия ядра
ls /root/.mihomo_secret 2>/dev/null # секрет API (если API защищён)
```

Если у API есть секрет, положите его в `/root/.mihomo_secret` (`chmod 600`). Если секрета нет, скрипты используют заголовок `X-No-Auth: 1`. Совет: порт API 9090 лучше не открывать наружу и желательно задать секрет.

## Шаг 3. Безопасная замена конфига

Копируем файлы через ПК (на роутере нет доступа к приватному репозиторию):

```powershell
scp cfg-rollback.sh router-remote1:/tmp/cfg-rollback.sh
scp apply-config.sh router-remote1:/tmp/apply-config.sh
scp config.yaml    router-remote1:/opt/clash/config.yaml.new
ssh router-remote1 "sha256sum /opt/clash/config.yaml.new"   # сверьте с файлом на ПК
```

Проверьте, что в файлах нет символов `\r` (из Windows): `ssh router-remote1 "grep -c $(printf '\r') /tmp/*.sh"` должно дать 0. Если нет - `sed -i 's/\r$//' /tmp/*.sh`.

Запуск:

```sh
ssh router-remote1
sh /tmp/apply-config.sh
```

Скрипт по порядку: делает бэкап `config.yaml.bak-ГГГГММДД` (с суффиксом b, c... если занято), проверяет новый конфиг ядром (`clash -t`), взводит откат на 10 минут, подменяет файл, перезагружает конфиг через API. Ожидаем **HTTP 204**.

### Что проверить после (пока таймер идёт)

- PID `clash` и `dnsmasq` **не изменились** (`pidof clash dnsmasq`).
- Порты слушают: `netstat -lnt | grep -E ':(9090|7894|1080) '`.
- DNS отвечает: `nslookup ya.ru 127.0.0.1`, `nslookup github.com 127.0.0.1`.
- В `logread | tail -50` нет ошибок clash.
- Сайты открываются с устройства в сети роутера; `tailscale status` показывает узел живым.
- sha256 рабочего `config.yaml` совпадает с файлом в репозитории.

Всё хорошо - **снимите маркер**: `rm /tmp/cfg_rollback` (скрипт-таймер сам увидит это и выйдет за ≤10 с). Не уверены - ничего не делайте, через 10 минут старый конфиг вернётся. Через 30-60 минут посмотрите лог cron-обновления правил (`logread | grep clash-rules`).

Ручной откат: `cp -p /opt/clash/config.yaml.bak-ГГГГММДД /opt/clash/config.yaml`, затем тот же `PUT /configs?force=true`.

## Шаг 4. Обновление ядра (Prizrak-Core)

Скрипт `core-update.sh` с конфигом `core-update.conf` (в вашем репозитории) умеет: `--check`, `--status`, `--list`, `--install --yes`. Он выдерживает новый релиз 240 минут, проверяет sha256, пробует `clash -v` и `-t` с текущим конфигом, делает копию старого ядра в `/tmp/core-backup` (в ОЗУ, пропадает при перезагрузке), заменяет ядро, проверяет здоровье и при сбое откатывает.

Установка на удалённый роутер:

1. В `core-update.conf` сначала оставить `AUTO_INSTALL=0`, cron только на проверку (например `20 * * * *`, `35 * * * *` и `50 * * * *` у трёх роутеров, чтобы запуски не совпадали). Автоустановка - в разделе ниже.
2. Копирование - через ПК, с проверкой sha256 и `\r`, затем `chmod +x`.
3. Запуск вручную, независимо от ssh:

   ```sh
   setsid /root/core-update.sh --install --yes >/tmp/core-install.log 2>&1 </dev/null &
   ```

   Дальше смотрим `/tmp/core-install.log`; в конце должно быть «ядро заменено: ..., Mihomo работает».
4. Перед установкой: время не около :00/:30 и 04:30, нет других `core-update.sh`, на `/tmp` не менее ~120 МБ, на `/overlay` есть запас (новое ядро может занять заметно больше прежнего - смотрите `df /overlay` заранее).
5. Устанавливаем **по одному роутеру**, после каждого - проверка: версия `clash -v`, порты, nft-таблица `inet clash`, DNS, `logread` без ошибок. PID clash и dnsmasq при замене ядра меняются - это нормально.

Копию старого ядра, если нужен долгий запас, скачайте на ПК до 04:30: `ssh router "cat /tmp/core-backup/<файл>.gz" > core-old.gz`.

### Включение автоустановки ядра (после успешной ручной замены)

Автоустановка на удалённом роутере меняет ядро без вас: служба останавливается на 10-30 секунд, перезапускаются dnsmasq и firewall. Скрипт откатывает ядро только по здоровью процесса и API, а доступность Tailscale не проверяет. Включайте, только если принимаете этот риск.

1. Сначала проверьте **реальное** время ежедневной перезагрузки, а не то, что написано в конфиге: `grep reboot /etc/crontabs/root`.
2. Приведите `REBOOT_TIME` в `core-update.conf` к этому времени. Иначе защитное окно `REBOOT_GUARD_MIN` (по умолчанию 20 минут до перезагрузки) считается от старого времени, и установка может стартовать прямо перед перезагрузкой.
3. Сделайте копию конфига (`cp -p core-update.conf core-update.conf.bak-ГГГГММДД`), правьте во временном файле, сверьте с оригиналом построчно (на BusyBox нет `diff`, подойдёт `awk`), проверьте число строк и только потом `mv`.
4. Поменяйте `AUTO_INSTALL=0` на `AUTO_INSTALL=1`. Перезапускать службы не нужно: скрипт читает конфиг при каждом запуске. `core-update.sh --status` должен показать «автоустановка: включена».
5. Условия установки по cron: с публикации релиза прошло `SOAK_MINUTES` (240) минут, роутер работает дольше `MIN_UPTIME_MIN` (10) минут, до перезагрузки больше `REBOOT_GUARD_MIN` минут. Если на роутере уже стоит последний релиз, ближайший запуск ничего не сделает. Если стоит старый, а релиз старше 240 минут, замена случится при ближайшем запуске cron: будьте в этот момент на связи.
6. Откат правки: вернуть копию `core-update.conf.bak-...` на место `core-update.conf`.

Замечание: для некоторых релизов контрольная сумма не опубликована, и скрипт пропускает её сверку. Тогда целостность подтверждает только проверка `clash -v`/`-t` и запуск. Сравните размер или хеш установленного ядра с роутером, где оно уже работает.

## Чего НЕ делать на удалённых роутерах

- Не включать автоустановку ядра, пока ручная замена на этом роутере не прошла чисто, и не оставлять `REBOOT_TIME` в конфиге не равным реальной перезагрузке. Не применять конфиг через `restart` без нужды.
- Не копировать секрет API на другие роутеры и не публиковать его.
- Не снимать маркер отката «на всякий случай» сразу после замены.
- Не запускать таймер-откат просто через `&` в ssh-сессии: он умрёт вместе с сессией, нужен `setsid`.
- Не гонять на BusyBox команды, которых там нет (`diff`, `nc -z`, `date +%N`).

## Мелочи, которые стоит знать

- Ежедневная перезагрузка (у автора сначала 04:30, с 01.11.2026 - 04:45, чтобы не пересекаться с обновлением правил в :30) сбрасывает всё в `/tmp`: скрипт отката, лог, RAM-копию ядра. Файлы в `/opt/clash` и `/root` остаются.
- Время в логах роутера и в Tailscale может быть в разных часовых поясах - сверяйте.
- Лишний upstream `127.0.0.1#7874` в dnsmasq безвреден, если в `dns:` нет `listen` на этом порту.
- Если вы управляете роутерами через Claude Code, держите правила (окна, шаги, запрет снимать маркер без вашей команды) в `CLAUDE.md` папки проекта.
